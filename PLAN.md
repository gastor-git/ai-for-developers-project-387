# PLAN.md

**Описание проекта**
Проект web приложения `Календарь бронирований`.
В проекте есть две условные роли: `Владелец календаря` и `Гость`.
В проекте нет регистрации и авторизации.

Владелец календаря — один заранее заданный профиль. Для Владельца существет страница, адрес которой строится по id профиля Владельца.
Гость бронирует слоты без создания аккаунта и без входа в систему.

Владелец календаря может:

- создавать события. Для этого он переходит на страницу своего профиля.
- для каждого события задавать: название, описание и длительность в минутах.
- копировать ссылку на странцу события в буфер обмена (для того чтобы отправить эту ссылку Гостю).
- на отдельной странице просматривать инфорацию о бронированиях Гостей. На этой странице в виде списка показаны бронирования всех типов событий от всех Гостей.

Гость может:

- посмотреть страницу с событиями Владельца, где доступно название события, описание и длительность. Адрес страницы сторится по id профиля Владельца и по id события.
- забронировать слот времени (в зависимости от длительности события) на определенную дату в ближайшие 14 дней. Для этого Гость должен выбрать тип события, при зтом открыватеся календарь и отображаеются свободные слоты времени на определенную дату в ближайшие 14 дней.
- создать бронирование на выбранный слот.

Правило занятости:
На одно и то же время нельзя создать две записи, даже если это разные типы событий.

Окно записи по умолчанию:
Доступные слоты формируются на 14 дней, начиная с текущей даты.
Гость может записаться только на свободный слот из этого окна.

Пример похожего приложения: https://cal.com. Нам нужен сильно упрощенный аналог.

**Архитектура и стек**
Проект реализуется с использованием REST API.
Бэкенд на golang, фронтенд на Vue.js + VITE.
Для хранения данных используем SQLite.
Запуск проекта в docker. Бэкенд, фронтенд и БД отдельными сервисами.

Первым этапом нужно реализовать спецификацию в формате TypeSpec. Спецификация должна зафиксировать API-контракт, по которому в дальнейшем будут независимо друг от друга разрабатываться бэкенд и фронтенд.
