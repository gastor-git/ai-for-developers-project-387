# CONTRIBUTING

## Сообщения коммитов (Conventional Commits)

Все коммиты пишутся по спецификации
[Conventional Commits](https://www.conventionalcommits.org/en/v1.0.0/):

```
type(scope): subject
```

- `subject` — краткое описание на русском (без точки в конце);
- `scope` — необязательный, уточняет область изменения (например `backend`,
  `frontend`, `spec`, `ci`, `e2e`).

Примеры:

```
feat(backend): добавлена генерация слотов
fix(frontend): починен выбор даты в календаре
docs: обновлён README
ci: добавлен запуск E2E-тестов в GitHub Actions
chore(deps): обновлены зависимости frontend
```

### Основные типы и влияние на версию

| Тип          | Семантика                        | Версия (SemVer) |
|--------------|----------------------------------|-----------------|
| `feat`       | Новая функциональность           | minor           |
| `fix`        | Исправление ошибки               | patch           |
| `docs`       | Только документация              | —               |
| `refactor`   | Рефакторинг без изменения поведения | —             |
| `perf`       | Оптимизация производительности   | —               |
| `test`       | Тесты                            | —               |
| `ci`         | Изменение CI/пайплайнов          | —               |
| `build`      | Сборка/зависимости               | —               |
| `chore`      | Обслуживание (не код/фичи)       | —               |
| `revert`     | Откат коммита                    | —               |

Breaking change: добавляется `!` после типа/скоупа (`feat!:` / `feat(scope)!:`)
или строка `BREAKING CHANGE:` в теле коммита → **major**.

### Почему это важно

- История коммитов понятна и пригодна для автоматического анализа.
- `release-please` по истории коммитов автоматически формирует release-PR:
  генерирует `CHANGELOG.md` и предлагает следующую версию по семантическому
  версионированию (тег `vX.Y.Z`).
- Релизы собираются автоматически после мёржа release-PR в `main`.

## Проверки перед коммитом

```sh
make spec          # перегенерировать OpenAPI-контракт
make spec-validate # валидация контракта Redocly
make test          # тесты бэкенда
make test-e2e      # E2E-тесты Playwright
```

Фронтенд: `cd frontend && npm run lint && npm run build`.
